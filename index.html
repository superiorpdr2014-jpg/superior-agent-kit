終端機就是那個「黑黑的、只能打字」的視窗。看起來很硬派，但你要做的只有一件事：把 Claude Code 叫出來，然後用中文跟它講話。不用背任何指令。

03第三步：CLAUDE.md 完整範本

存成 CLAUDE.md，放在你的專案資料夾最上層。每次開工它都會自動讀一遍。

把上一段「關於我」貼給 AI，跟它說「照這段幫我整理成 CLAUDE.md」，它就會生出下面這種東西。你也可以直接複製這份改。

開檔前

先開一個專案資料夾，不要在系統最上層開

建一個資料夾當它的「辦公室」，例如 協會_Agent，把相關檔案丟進去（合約、報價單、會員名冊、活動照片、逐字稿、Logo）。它讀得到才幫得上忙。

不要在「使用者」或 C 槽最上層啟動——它會把整台電腦當工作區。不同的事開不同資料夾，記憶才不會打架。

CLAUDE.md · 把（　）換成你自己的

## 身份設定
- 你是「（AI 的名字）」，（你的名字）的 AI 助理與分身。
- 本專案是（公司／協會名）的（用途，例如：營運管理系統）。

## 使用者資訊
- 慣用稱呼：（你希望它怎麼叫你）

- 一律使用繁體中文，除非我指定其他語言。
- 語氣親近、口語、不制式、不官方——像朋友聊天。

04第四步：安全三件套

誤刪一次就知道值不值得。十分鐘，做完可以放心把速度開到最大。

三層，缺一不可：① 刪除進資源回收筒 ② 最危險的指令直接封鎖 ③ 選對權限模式。裝了第一層不代表安全，因為 AI 可能選到別的刪除方式，所以第二層一定要有。

3-1 · 讓「刪除」變成可以反悔

裝一個小工具，讓刪掉的檔案進資源回收筒，而不是直接消失。

Windows PowerShell 或終端機執行 
npm install -g trash-cli
macOS 有 Homebrew 的話 
brew install trash

裝完之後，這條規則要寫進你的 CLAUDE.md（上面的範本裡已經有了）：

加進 CLAUDE.md 的行為規範 
- 刪除檔案一律優先用 trash（丟資源回收筒，可還原），不要用 rm。
- 真的需要永久刪除時，先列出要刪的目標清單並取得我確認，才執行。

3-2 · 危險指令黑名單

這一層是真正的煞車。把「出事就救不回來」的那些指令永久封鎖——黑名單的優先權高於任何權限模式，就算你開全速，這些還是會被擋下來。

檔案位置

Windows：C:\Users\你的使用者名稱\.claude\settings.json
macOS／Linux：~/.claude/settings.json

如果這個檔案已經存在且裡面有東西，不要整份覆蓋——把 deny 這段合併進去就好。不確定怎麼合併，就把整段貼給 AI，叫它「幫我合併進現有設定，改之前先備份」。

settings.json · 我自己在用的這一份 
{
  "permissions": {
    "defaultMode": "bypassPermissions",
    "deny": [
      "Bash(rm -rf *)",
      "Bash(rm -fr *)",
      "Bash(rm -r *)",
      "Bash(rm -R *)",
      "Bash(rm -f *)",
      "Bash(sudo *)",
      "Bash(dd *)",
      "Bash(mkfs*)",
      "Bash(diskutil erase*)",
      "Bash(chmod 777 *)",
      "Bash(chmod -R 777 *)",
      "Bash(git reset --hard*)",
      "Bash(git push --force*)",
      "Bash(git push -f *)",
      "Bash(git clean -f*)",
      "Bash(git branch -D*)",
      "Bash(shutdown*)",
      "Bash(reboot*)",
      "Bash(: >*)",
      "Bash(truncate *)"
    ]
  }
}
被擋的指令它會幹什麼
rm -rf一秒刪光整個資料夾，不進資源回收筒，救不回來
sudo用最高權限做事，可以動到系統檔
git reset --hard
git push --force		抹掉你的工作紀錄，或把別人的版本蓋掉
dd / mkfs
diskutil erase		直接寫硬碟、格式化磁碟
shutdown / reboot把你的電腦關掉或重開
chmod 777把檔案權限全開，等於門戶大開

3-3 · 選一個權限模式

權限模式決定「它動手前會不會先問你」。四種，用終端機裡的 Shift + Tab 循環切換。

模式白話說明會問你嗎適合誰
Default每個動作都先問過你每次都問剛入門，還想看它在幹嘛
Plan只規劃不動手，你確認後才執行你主動觸發大工程，想先看全貌
Accept Edits改檔案不問，跑指令還是會問部分問新手建議從這個開始
Bypass什麼都不攔，全部直接執行完全不問我用這個，但一定要先做完 3-1、3-2
我的看法

為什麼我開 Bypass

做一份簡報要建二十個檔案、跑三十個指令。每一個都跳出來問「要不要執行？」，你會一直按 Enter 按到麻木，而且根本沒在看。

按到麻木的確認，等於沒有確認——那是假的安全感。真正的安全是那份黑名單。所以順序很重要：先架好煞車，再踩油門。

驗收

叫你的 AI：「幫我確認 settings.json 的 deny 清單已經生效，用一個一定會被擋下來的假指令示範給我看，不要真的刪任何東西。」

05第五步：給它長出手腳

大腦再強，碰不到你的東西也沒用。這一段是讓它真的能動手。

有四條路可以讓 AI 操作你的軟體。你不需要背，只要知道有這四條，然後問它「這件事該走哪一條」。

方式是什麼什麼時候用
API軟體官方開的後門，最快最穩對方有提供，而且你要大量／自動處理
CLI指令列工具，AI 用起來最順手檔案處理、影音轉檔、語音轉文字、上傳網站
MCP專門給 AI 用的標準插座你要它「常態性」使用某個服務
瀏覽器控制直接操作網頁，像人一樣點沒 API、要登入、畫面才看得到的資料

判斷原則：有 API 走 API，沒有就走 CLI，要常用就包成 MCP，都不行才用瀏覽器硬爬。

安全提醒 · 很重要

每接一個工具，就是多交一把鑰匙

MCP 會把外部服務的資料和操作權交給 AI。第一次一律開最小範圍，能只讀就先只讀；等到真的需要建立、修改、寄送的時候，再逐項加上去。

API Key 和密碼只放在本機設定或環境變數，絕對不要寫進會上傳的檔案、Markdown 或聊天訊息裡。

我實際在用的三個

① Playwright · 操作瀏覽器（爬社群、抓後台資料、自動截圖） 
claude mcp add --scope user playwright -- npx @playwright/mcp@latest --isolated

Instagram、Facebook 這類要登入、畫面又是動態長出來的網站，只能走這條。--isolated 是讓它用獨立的瀏覽器，不要接管你平常已登入私人帳號的那個。

② Firecrawl · 把網頁變成 AI 讀得懂的文字（要先去官網申請免費 API Key） 
claude mcp add --scope user firecrawl \
  --env FIRECRAWL_API_KEY=你自己的KEY \
  -- npx -y firecrawl-mcp

用來讀公開網頁、整理文章、比較產品頁。到 firecrawl.dev 免費註冊拿 Key，Key 是你自己的，不要放進公開專案。

③ Filesystem · 讓它讀寫指定的其他資料夾 
claude mcp add --scope user filesystem -- \
  npx -y @modelcontextprotocol/server-filesystem 你要開放的資料夾絕對路徑

新手先開一個資料夾就好，不要一開始就把整個桌面、下載、文件全部開放。

看看目前裝了哪些 
claude mcp list

請一步一步教我怎麼授權給你，每一步都告訴我要點哪裡、
畫面上會看到什麼。

先只開「唯讀」權限就好，等我確定沒問題再說。
過程中需要我提供什麼，直接問我，不要自己猜。
驗收

每裝完一個工具，用不會改動任何資料的方式驗證：叫它讀一個公開網頁回報標題、或列出資料夾第一層的檔名。不要為了測試就寄信、刪檔或建立行程。

06第六步：讓它記得住

CLAUDE.md 記的是「你是誰」，這一層記的是「發生過什麼」。

AI 最大的問題是失憶。你這禮拜糾正過它的事，下禮拜它又犯一次。解法是把每一次糾正都變成一個檔案——一件事一個檔，另外用一份 MEMORY.md 當目錄，一行一條。

先貼這句，讓它學會自己記 
從現在開始，只要發生以下任何一種情況，
請你主動把它寫成一個記憶檔存起來，
並在 MEMORY.md 加一行索引，不用等我叫你：

1. 我糾正你「不對，我們這邊是這樣」
2. 你踩到一個坑，花了時間才解決
3. 我告訴你一件關於我們組織的事實
4. 我們一起做了一個決定

記憶檔請用這個格式：
---
name: 短的英文檔名
description: 一句話說明這條在講什麼
metadata:
  type: user | feedback | project | reference
---
（內容本體，寫清楚 Why 和 How to apply）

寫完念一遍給我聽，我確認過再存。
記憶檔長這樣（我的真實例子，內容改過） 
---
name: event-signup-sheet-append
description: 活動報名資料一律用累加，不可覆寫舊資料
metadata:
  type: feedback
---

活動報名的試算表，每個月一個分頁。
新資料要「加在下面」，不是把整欄蓋掉。

**Why:** 曾經直接覆寫，把上半個月的 40 筆報名洗掉，
       只能從信箱一封一封找回來。
**How to apply:** 寫試算表之前，先讀出現有的最後一列，
       從下一列開始寫。寫完回報一共新增幾筆。
關鍵心法

越用越像你，靠的就是這個迴路

每次它做錯、或你講了一句「不對，我們這邊是這樣」，就叫它把這條寫成記憶。三個月後，它會比新來的員工還懂你們組織。

我現在累積了八十幾條，從「某某分店的通知帳號壞了」到「我的名字常被打錯成哪個字」都在裡面。

07現成任務包

設定完不知道先做什麼？從這三個開始，都是三十分鐘內看得到成果的。

任務一 · 例會錄音 → 會議紀錄（投報率最高） 
我把（會議名稱）的錄音檔放在這個資料夾了。

請你：
1. 轉成逐字稿，標上時間軸和講話的人
2. 整理成一份會議紀錄，分成「決議事項」「待辦事項」
   「下次追蹤」三段，待辦要標出負責人和期限
3. 決議事項用紅字標出來
4. 輸出成一份可以直接寄出去的檔案

不確定誰在講話的地方，先標「（待確認）」不要亂猜。
任務二 · 報名名單一條龍

1. 讀出目前所有報名資料，告訴我幾筆、有沒有重複或缺漏
2. 依（分組條件）幫我分組，整理成一張出席表
3. 幫我擬一封通知信，用我的口氣寫，親近一點不要制式

信先寫給我看，我確認過再說要不要寄。
在我明確說「可以寄了」之前，絕對不要真的寄出去。
任務三 · 一段訪談 → 一整套內容 
這是（受訪者）的訪談錄音／逐字稿。

請幫我做出這四樣，全部用我的口氣：
1. 一篇 800 字左右的故事文章
2. 三則社群貼文（一則短鉤子、一則長文說故事、一則走心的）
3. 一段 60 秒短影片的口白稿
4. 上面文章的英文版

寫之前先告訴我你抓到的三個重點，我確認方向再往下寫。

開店的人先做這五個

包膜、美容、鈑烤、中古車、汽材、洗車——這幾件事每一家店都在做，也每一家店都在漏。

任務四 · LINE 詢問不漏接（最痛的那個） 
我的 LINE 官方帳號每天有很多詢問，忙起來就漏掉。

請幫我：
1. 把最近 30 天「客人問了但我沒回」的對話整理成一張清單，
   標出多久沒回、最後一句是什麼
2. 依內容分類：問價格 / 問地址時間 / 想預約 / 其他
3. 每一類擬一組罐頭回覆，用我的口氣，不要制式
4. 告訴我哪幾則現在補回還來得及，哪幾則大概已經跑掉了

先給我清單，我確認過再談要不要回。
在我說可以之前，不要真的發任何訊息給客人。
任務五 · 客人問價格 → 一張估價單 
這是我的價目表（我放在資料夾裡了）。
客人傳來的訊息是：（把客人的話整段貼進來）

請幫我：

2. 做成一張可以直接傳給客人的估價單

4. 寫一則走心版短文

全部用我平常講話的口氣。

請幫我把品名、規格、數量、單價、金額整理進試算表的
「進貨」分頁，一張單一列，並在最後加總。

08大家最常問我的

例會現場被問到的問題，我先寫在這裡。

一個月要花多少錢？

USD 20（約台幣 600）起跳，一開始買最便宜的方案就夠用。真的做到重度使用才需要往上升級。不用先買貴的，用不完的。

我電腦很爛，跑得動嗎？

跑得動。思考是在雲端做的，你的電腦只負責開檔案、跑指令。只有影音轉檔、語音轉文字那種才吃效能，那些可以先跳過。

它會不會亂改我的檔案？

會，如果你不設限的話。所以安全三件套一定要先做：刪除進資源回收筒、危險指令黑名單、選對權限模式。新手先用 Accept Edits。

我的資料會不會外流？

你電腦裡的檔案不會自己上傳，但你貼給它看的內容會送到雲端處理。客戶個資、身分證、金流帳號這類，先去識別再貼——例如把姓名換成「客戶 A」。

學不會怎麼辦？

卡住就截圖丟給它問，不要自己 Google。它看得懂錯誤訊息，也會一步一步帶你。這是唯一一個「你不會用，可以直接問它本人」的工具。

多久會有感覺？

前兩個禮拜你會覺得自己很蠢——一直問問題、一直做壞。撐過去，之後每一天都在複利。門檻不是技術，是願意在一開始暫時變笨。

09我踩過的坑

每一條後面都有一次真實的損失。學結論就好，不用學過程。

  • 絕對不要用正式資料做測試。我測「權限夠不夠」的時候換成有權限的帳號重跑，結果真的寄出六封信、真的把課程下架了。要測就用假資料，或用一個不存在的編號。
  • AI 的判斷不能直接對外承諾。它說「這個看起來可以修復」，客人到店發現要烤漆，當場翻臉。現在的規則是：AI 判讀給內部參考，對外一律「需要現場評估」。技術可以很強，但承諾要由人來做。
  • 不要一次要它做完。「幫我做一整套系統」會得到一坨爛東西。一次一個功能，做完測試，再下一個。
  • 它會忘記，所以要逼它寫下來。同一個坑我踩過三次，因為前兩次沒叫它寫記憶檔。
  • 上線後才是開始。做給別人用的東西，一定會出現你在辦公室測不出來的狀況。留時間修，不要做完就當結案。
  • 別人的設定包不要照抄。網路上很多現成的技能包，裝下去等於讓 AI 照著陌生人寫的指令做事。先叫它「幫我看一下這個是什麼、適合我們嗎」，再決定裝不裝。
  • 金鑰和密碼要藏好。很容易不小心把帳號密碼寫進檔案裡上傳出去。定期叫它「幫我檢查這個資料夾裡有沒有不該外流的密碼或金鑰」。
  • 先承認做不到的事。有些限制是技術上真的解不掉的。承認限制，才能把做得到的部分做到最好。
最後一件事

門檻不是技術，是願意在一開始暫時變笨

前兩個禮拜你會覺得自己很蠢，一直問問題、一直做壞。大部分人在這裡放棄，回去用原本的方法。

撐過去，之後每一天都在複利。給你一張地圖，路還是要你自己走。
